# Receipt Reader — อ่านใบเสร็จด้วย LLM บนเครื่อง แล้วบันทึกลงฐานข้อมูล

อัปโหลดรูปหรือ PDF ใบเสร็จ / ใบกำกับภาษี → โมเดล vision ที่รันบนเครื่อง (Ollama) อ่านออกมาเป็น JSON →
ตรวจด้วยกฎบัญชี (ยอดรวม, VAT 7%, เลขผู้เสียภาษี, ปี พ.ศ.) → คนตรวจ/แก้บนหน้าจอเทียบกับรูป → อนุมัติ → ลง PostgreSQL

ข้อมูลไม่ออกนอกเครื่อง ไม่มีค่า API

```
backend/   .NET 10 Clean Architecture (Domain / Application / Infrastructure / Api) + xUnit
frontend/  Angular 21 (standalone, signals, zoneless) + ng-zorro-antd (Ant Design) + Tailwind (layout)
docs/      architecture.md — flow, DB schema, กฎตรวจ, แนวทางพัฒนาต่อ
```

## เริ่มใช้งาน

### ทางที่ 1: Dev (แนะนำตอนพัฒนา)

ต้องมี: .NET 10 SDK, Node 22+, Docker, [Ollama](https://ollama.com) (บน Windows ติดตั้งแบบ native จะใช้ GPU ง่ายสุด)

```bash
# 1) Postgres (และ Ollama ถ้าไม่ได้ติดตั้งแบบ native — ลบ service ollama ในไฟล์ออกถ้าติดตั้งแล้ว)
docker compose -f docker-compose.dev.yml up -d db

# 2) โหลดโมเดล (~6 GB, ครั้งเดียว)
ollama pull qwen2.5vl:7b

# 3) API → http://localhost:5080  (สร้างตารางให้อัตโนมัติตอนเริ่ม)
cd backend
dotnet test                                  # รัน unit test ของกฎตรวจ
dotnet run --project src/ReceiptReader.Api

# 4) UI → http://localhost:4200  (proxy /api ไปที่ :5080)
cd frontend
npm install
npm start
```

### ทางที่ 2: Docker ทั้งชุด

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec ollama ollama pull qwen2.5vl:7b
# เปิด http://localhost:8080
```

> ใช้ GPU ใน Docker บน Windows ต้องมี WSL2 + NVIDIA driver ล่าสุด (Docker Desktop รองรับ `--gpus` แล้ว)
> ถ้าไม่อยากยุ่ง ให้ติดตั้ง Ollama แบบ native แล้วตั้ง `OLLAMA_BASE_URL=http://host.docker.internal:11434` ใน `.env`
> และรัน `docker compose up -d --build db api web`

ตรวจสถานะได้ที่ `GET /api/health` (แถบบนขวาของ UI ก็แสดง DB / Ollama)

**ลองครั้งแรก:** ลาก `samples/sample-receipt.jpg` (ใบเสร็จจำลอง ร้านสมมติ) เข้าหน้าเว็บ — ควรได้ยอด 245.00, VAT 16.03,
วันที่ 2026-10-13 (จาก 13/10/69), เลขผู้เสียภาษีผ่าน checksum แล้วค่อยลองกับใบเสร็จจริงของคุณ

## เลือกโมเดลและโหมดการอ่าน

ตั้งใน `backend/src/ReceiptReader.Api/appsettings.json` → `Extraction` (หรือ env ใน `.env`)

| Mode | ทำงานอย่างไร | ใช้เมื่อ |
|---|---|---|
| `Vision` (default) | รูป → vision LLM → JSON ในครั้งเดียว | เริ่มต้น เร็ว ตั้งค่าน้อย |
| `OcrThenLlm` | รูป → OCR model ถอดข้อความ → text LLM จัดเป็น JSON | ใบเสร็จไทยตัวเล็ก/ซีด อ่านพลาดเยอะ |

- `VisionModel` — ค่าเริ่มต้น `qwen2.5vl:7b` ลองรุ่นใหม่กว่าได้ (เช่น Qwen-VL รุ่นถัดไป, Gemma ที่รับรูป) แค่ `ollama pull` แล้วเปลี่ยนชื่อ
- `OcrModel` — สำหรับภาษาไทยลอง **Typhoon OCR** (SCB 10X) ถ้ามี build สำหรับ Ollama ให้เช็กชื่อ tag ล่าสุดบน ollama.com / Hugging Face
- `TextModel` — โมเดลข้อความทั่วไป เช่น `qwen2.5:7b`
- RTX 5080 (16 GB) รันโมเดล 7–12B แบบ quantized ได้สบาย ใบละประมาณ 3–15 วินาทีแล้วแต่รุ่น

ชื่อรุ่นโมเดลเปลี่ยนเร็ว ควรลองหลายตัวกับใบเสร็จจริงของคุณ แล้วดูจำนวน Error/Warning ในหน้ารายการเทียบกัน

## บริษัท ฝั่งซื้อ-ขาย และบัญชี

1. **บริษัท** — สร้างโปรไฟล์ (ชื่อ เลขผู้เสียภาษี สาขา ที่อยู่ จด VAT หรือไม่) แต่ละบริษัทมีผังบัญชีของตัวเอง (สร้างให้อัตโนมัติ แก้/เพิ่มได้)
   เลือกบริษัทที่มุมซ้ายบน — ทุกหน้าทำงานกับบริษัทที่เลือก
2. **ฝั่งซื้อ / ฝั่งขาย** — อัปโหลดเข้าแท็บไหน เอกสารเป็นฝั่งนั้น ฝั่งเราเติมจากโปรไฟล์ AI อ่านเฉพาะคู่ค้า
   (ผู้ขายเมื่อซื้อ ผู้ซื้อเมื่อขาย) — AI ยังอ่านเลขผู้เสียภาษีฝั่งเราไว้เทียบ ถ้าไม่ตรงจะเตือนว่าเลือกบริษัท/ฝั่งผิด
3. **งวดบัญชี (รายเดือน)** — เอกสารอยู่ในงวดตามเดือนของวันที่ ย้ายงวดได้ (ภาษีซื้อขอคืนได้ภายใน 6 เดือน, ภาษีขายต้องอยู่เดือนเดิม)
   หน้างวดบัญชีสรุปซื้อ/ขาย/VAT ต้องชำระ ต่อเดือน และ **ปิดงวด** ได้เมื่ออนุมัติครบ — ปิดแล้วแก้เอกสารและการชำระในเดือนนั้นไม่ได้
4. **การชำระเงิน (เจ้าหนี้/ลูกหนี้)** — ใบกำกับภาษี/ใบแจ้งหนี้ที่อนุมัติเป็นยอดค้าง บันทึกจ่าย/รับเงินได้หลายครั้ง (วันที่ จำนวน บัญชีเงินสด/ธนาคาร)
   ใบเสร็จรับเงินถือว่าชำระแล้วตอนอนุมัติ · หน้าค้างชำระแยกอายุหนี้ (ยังไม่ครบกำหนด, 1-30, 31-60, …)
5. **ใบลดหนี้ / ใบเพิ่มหนี้** — AI อ่านเลขที่ใบกำกับที่อ้างอิง ระบบเชื่อมกับใบเดิม (คู่ค้าเดียวกัน) และปรับยอดค้างของใบเดิมให้
6. **บัญชีคู่ (Dr/Cr)** — สร้างจากเอกสารที่อนุมัติและการชำระเงินโดยอัตโนมัติ (ไม่เก็บซ้ำ จึงตรงกับเอกสารเสมอ):

   | เหตุการณ์ | เดบิต | เครดิต |
   |---|---|---|
   | ซื้อ (ใบกำกับเต็มรูป) | ค่าใช้จ่ายตามบัญชีที่เลือก + ภาษีซื้อ | เจ้าหนี้การค้า |
   | ซื้อ (อย่างย่อ/ใบเสร็จ หรือบริษัทไม่จด VAT) | ค่าใช้จ่ายรวม VAT | เจ้าหนี้การค้า |
   | จ่ายเงิน | เจ้าหนี้การค้า | เงินสด / ธนาคาร |
   | ขาย | ลูกหนี้การค้า | รายได้ + ภาษีขาย |
   | รับเงิน | เงินสด / ธนาคาร | ลูกหนี้การค้า |
   | ใบลดหนี้ | กลับด้านของใบกำกับ (ขาย → รับคืนและส่วนลด) | |

   หน้าสมุดรายวันดูรายการรายเดือน งบทดลอง และดาวน์โหลด CSV

## สอน AI

- **เรียนจากตัวอย่าง (ไม่ต้อง fine-tune)** — อนุมัติเอกสารที่มีเลขผู้เสียภาษีผู้ขายถูกต้อง → ระบบเก็บใบล่าสุดของผู้ออกเอกสารรายนั้นเป็นตัวอย่าง (3 ใบ)
  ใบใหม่ที่อ่านรอบแรกไม่ผ่านการตรวจสอบ จะอ่านซ้ำโดยแนบตัวอย่างแล้วเลือกผลที่ดีกว่า · ปักหมุดใบที่ดีที่สุดไว้ได้ (ไม่ถูกแทนที่) ลบใบที่ผิดออกได้
- **วัดผล** — เทียบสิ่งที่ AI ตอบ (`raw_extraction`) กับค่าที่คนอนุมัติ รายช่อง รายโมเดล รายเดือน และรายการใบที่ต้องแก้มากที่สุด
- **Dataset** — ดาวน์โหลด zip (รูป + `train.jsonl`) ไปใช้ fine-tune โมเดล vision เช่น Unsloth / LLaMA-Factory แล้ว `ollama create`
- บัญชีที่ใช้กับคู่ค้ารายเดิมล่าสุด จะถูกเติมให้อัตโนมัติ

## หน้าจอ

- **เอกสาร** — แท็บซื้อ/ขาย, เลือกงวด, ลากไฟล์มาวาง, แท็บตามสถานะ, ค้นหา, สถานะการชำระ
- **ตรวจ** — รูปซ้าย ฟอร์มขวา (ฝั่ง งวด ครบกำหนด บัญชี คู่ค้า รายการพร้อมส่วนลดต่อบรรทัด), ตรวจสดขณะแก้,
  บันทึกการจ่าย/รับเงิน, ดูรายการ Dr/Cr ของใบนี้ · `Ctrl+S` บันทึก, `Ctrl+Enter` อนุมัติแล้วไปใบถัดไป
- **ค้างชำระ** · **งวดบัญชี** · **สมุดรายวัน** (+ งบทดลอง, CSV) · **สอน AI** · **บริษัท** (โปรไฟล์ + ผังบัญชี)
- **สต็อก › สินค้า** — หมวดสินค้า (รหัสหมวดห้ามซ้ำ เช่น BED; มีสินค้าแล้วลบไม่ได้ ให้ปิดใช้งาน), สินค้า (รหัสรันอัตโนมัติ BED-001,
  ประเภทสินค้า/บริการ, ยอดยกมาต่อคลังพร้อมต้นทุน → คงเหลือและมูลค่าแบบถัวเฉลี่ยเคลื่อนที่), ค้นหา/สแกนบาร์โค้ด (เครื่องสแกน USB หรือกล้องผ่าน https;
  สแกนตอนคีย์บอร์ดเป็นภาษาไทยก็หาเจอ), พิมพ์ป้ายบาร์โค้ด Code 128 (A4 24/40 ดวง, ม้วน 50×30 มม.) · **สต็อก › คลังสินค้า** — เพิ่ม/ลบคลัง, คลังหลัก 1 คลังต่อบริษัท
  ทุกคนดูได้ ผู้ดูแลระบบ/ผู้ดูแลบริษัทแก้ได้ (เอกสารซื้อขายยังไม่ตัดสต็อก — เฟสถัดไป)

## ข้อจำกัดของเวอร์ชันนี้

- **PDF** อ่านได้สูงสุด `Extraction:MaxPdfPages` หน้าแรก (ค่าเริ่มต้น 3) โดยแปลงเป็นรูปแล้วส่งให้โมเดล — ยังไม่ได้ดึงข้อความ/XML ของ e-Tax invoice ตรงๆ
- Schema จัดการด้วย EF migrations (รันอัตโนมัติตอน API เริ่ม) — ฐานข้อมูลเก่าที่สร้างด้วย `EnsureCreated` จะถูกบันทึกว่าผ่าน
  migration แรกแล้วอัปเกรดต่อให้เอง · เพิ่ม migration: `cd backend && dotnet tool restore && dotnet ef migrations add <ชื่อ>
  -p src/ReceiptReader.Infrastructure -s src/ReceiptReader.Api -o Persistence/Migrations`
- ยังไม่มียอดยกมา (opening balance) — งบทดลองนับจากเอกสารแรกในระบบ · ยังไม่รองรับภาษีหัก ณ ที่จ่าย และการรับ/จ่ายเกินยอด
- ไม่มีระบบ login — ถ้าใช้หลายคนให้ต่อ Entra ID / JWT เพิ่ม
- queue อยู่ใน process เดียว (เหมาะกับเครื่องเดียว GPU เดียว)
- `SixLabors.ImageSharp` ใช้ Six Labors Split License — ฟรีสำหรับใช้ส่วนตัว/บริษัทรายได้ไม่เกินเกณฑ์ ถ้าเอาไปใช้เชิงพาณิชย์ให้ตรวจเงื่อนไข หรือเปลี่ยนเป็น SkiaSharp
